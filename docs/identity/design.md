# DNS handles in the CLI

Gild account and agent IDs remain stable. A DNS handle is a mutable address; tokens, permissions, sessions and repository storage keep their existing IDs. This CLI consumes the site's generated contract and its shared `displayIdentity` source rather than implementing another identity formatter.

`gild whoami` requests the current identity and prints the handle and verification status. `--agent <label>` uses an approved agent token and prints the derived handle without `@`. `gild handle set <domain>` prints `_gild.<domain>` and `gild=<stable ID>`; `gild handle check` verifies DNS and refreshes the cached handle pointer. There is no HTTPS or `.well-known` verification method.

`gild clone <handle>/<repo>` resolves the repository through the API and uses its canonical `clone_url`. The shared API client follows a bounded number of same-origin redirects while retaining the HTTP method, request body and authentication. It rejects cross-origin redirects. Thus existing remotes and stored legacy runner addresses remain usable while new remotes use handles. Git's own smart HTTP redirect behavior is proven in the companion site integration suite.

Organization participant displays use the API's contextual display field, generated by `displayIdentity`. The shared formatter also supports Unicode IDNs, aliases, collisions, human-only `@` prefixes, owner details and mention resolution for future CLI TUI surfaces. There is no separate chat/TUI in this repository.

Validation: `bun test` passed 50 tests and 343 assertions; `bun run typecheck` passed; `bun run build` and `bun run pack` compiled all three configured targets (darwin arm64, darwin x64, linux x64). The npm wrapper was smoke-tested on this Intel Mac using darwin x64: version, auth init and auth status, with config and Git config isolated inside `.tmp`. Linux execution remains CI's platform smoke test.

`node scripts/handles-revert.mjs` proves five behavioral failures with individual fixes disabled: live whoami, TXT instructions, agent prefix, canonical git remote, and method-preserving redirects. It restores every source file in `finally`; the evidence is in `revert-evidence.json`.

Deployment requires the companion site's migration and Worker/render update. The CLI is built into an open PR only; this lane does not publish or release it. Other lanes must regenerate identity/contract changes from the site, retain IDs in stored data, use handle URLs in outward links and use `displayIdentity` for participant display.
